# Relay 自管账号（阿里云短信验证码）+ 禁用市场账号入口 — 实施计划

## 需求定案

1. **手机号是账号主体**：注册必须短信验证码；登录默认验证码（已注册手机号凭码登录、新号凭码注册，一次流程完成）；密码**可选**（允许无密码，设了可用密码登录作备选）。
2. **阿里云 SMS**：AccessKeyId/Secret、签名、模板 CODE 全部环境变量读取；凭据缺失时发码接口显式 503，其余功能不受影响。
3. **本地 refresh token**：access 15 分钟 / refresh 30 天轮换制，refresh 失效才需重新验码。
4. **彻底移除远程控制链路的 GitHub/官方身份登录**；同时**禁用市场账号入口**（纯浏览保留）：桌面端删除 `account_github_*` 命令与市场登录 UI，桌面不再依赖 `auth.openbitfun.com`；市场 Rust 客户端库代码保留（匿名 browse 继续用）。
5. 注册策略：开放自助注册 + `RELAY_LOCAL_REGISTRATION=closed` 开关 + relay-admin 建号。
6. 范围：relay 服务端 + mobile-web + 桌面端 + CLI。HarmonyOS/Android 应用不在范围（显式不支持）。

仓库兼容约束：`/api/auth/login` 不加必填字段；新能力走 `GET /api/info` capabilities 新增 `local_auth_v1`；`protocol_version` 保持 3；users 表新列走幂等 ALTER，旧数据不删不重置。

---

## Phase A — relay 服务端

### A1. 数据库（`relay-service/src/db.rs`）
- `users` 幂等加列：`password_hash TEXT NULL`、`failed_attempts INTEGER DEFAULT 0`、`locked_until INTEGER DEFAULT 0`
- 新表 `phone_identities(phone PK, user_id UNIQUE REFERENCES users, verified_at)`（参照 miniapp-market `email_identities` 先例）；`username` 列填生成句柄 `u-<6hex>`，**不落手机号**（Pages URL 是 `/p/{username}/{slug}`，防泄露）
- 新表 `local_auth_tokens(token_hash PK /* sha256 hex */, user_id, token_kind access|refresh, family_id, expires_at, created_at)`——只存哈希；access 15 分钟、refresh 30 天、轮换制，family 重放吊销全家
- 新表 `sms_codes(phone PK, code_hash /* HMAC-SHA256(secret, phone:code) */, expires_at, attempts, consumed_at, created_at)`——每号一个生效码，重发覆盖；TTL 5 分钟、最多 5 次尝试
- 本地账号 `user_id = local-<16hex>`；`UserRow` 带指数 lockout

### A2. 阿里云短信客户端（新模块 `relay-service/src/sms.rs`）
- REST 直连 `https://dysmsapi.aliyuncs.com`，`Action=SendSms`（SignName/TemplateCode/PhoneNumbers/TemplateParam={"code":"…"}），**V3 签名（ACS3-HMAC-SHA256）** 自实现（reqwest + sha2 + hmac；`hmac` 进 workspace 依赖、关默认特性；不引重型 SDK）
- 环境变量：`RELAY_SMS_ALIYUN_ACCESS_KEY_ID`、`RELAY_SMS_ALIYUN_ACCESS_KEY_SECRET`、`RELAY_SMS_ALIYUN_SIGN_NAME`、`RELAY_SMS_ALIYUN_TEMPLATE_CODE`、`RELAY_SMS_CODE_SECRET`（本地 HMAC 密钥；缺失→发码 503）
- 手机号 `1[3-9]\d{9}` 归一化（去 +86/空格）；6 位数字码；同号 60s 冷却 + 每日上限（10/号/天）+ per-IP 限流（复用 `LoginRateLimiter`）
- 单测用本地 mock HTTP server 断言签名与错误分支

### A3. 认证端点（`routes/auth.rs`；删除 `/api/auth/github/start|poll` 与 `identity.rs` 的 IdentityVerifier 远程验证/代理）
- `POST /api/auth/local/sms/send {phone}` → 202 同形响应（不区分号是否注册，防枚举）
- `POST /api/auth/local/login {phone, code}` 或 `{phone, password}`（二选一）→ `{accessToken, accessExpiresAt, refreshToken, refreshExpiresAt, user:{userId, login, phoneMasked, hasPassword}}`。验证码路径：已注册→登录；新号+注册开放→建号并登录；新号+closed→403。密码路径：无密码账号 401 统一文案，带 lockout
- `POST /api/auth/local/refresh {refreshToken}` → 轮换新对；重放已轮换 family → 吊销全家
- `POST /api/auth/local/password {newPassword}`（Bearer access token）→ 设置/修改可选密码；改密吊销该用户全部 token
- `verify_identity_credentials`（auth.rs:297）改为本地 access token 查验；`/api/auth/login` wire 形状不变
- `/api/info` capabilities 加 `local_auth_v1`；Pages 登录自动兼容，relay 内置 `web/page-auth-client.ts` 改手机号+验证码表单

### A4. 配置与管理
- `config.rs` 读 `RELAY_LOCAL_REGISTRATION`（open 默认/closed）+ 全部 `RELAY_SMS_*`；`docker-compose.yml`、`deploy/relay-v1` 增加透传
- relay-admin：保留 ListUsers/DeleteUser（显示句柄+掩码手机号）；新增 `SetPassword --phone`、`AddUser --phone --password-stdin`（closed 部署管理员建号，写入已验证 phone_identities）

### A5. 测试（`cargo test -p openbitfun-relay-service`）
验证码全流程（mock 短信）、登录注册合一、closed 拒新号、防枚举、码尝试上限/过期、密码可选路径与 lockout、refresh 轮换与重放吊销、token 哈希存储、`/api/auth/login` 幂等不变、github 路由 404、capability 广播、阿里云签名单测；改写原 github/identity 测试

## 风险与说明

- **升级兼容**：权威模式旧库用户无手机号/密码，需 admin `AddUser --phone` 绑定后方可登录（devices/pages 归属随 user_id 保留）；`/api/auth/login` 形状不变，新旧端由 `local_auth_v1` 探测兜底
- **短信依赖**：阿里云凭据缺失→发码 503、验证码登录不可用（密码登录仍可用），显式报错；`RELAY_SMS_CODE_SECRET` 轮换仅使在途验证码失效
- **防滥用**：per-IP 限流 + 同号 60s 冷却 + 每日上限 + 5 次尝试上限 + send 同形响应防枚举
- **市场功能**：浏览不受影响；投稿/收藏等账号操作因入口禁用而不可达，官方市场 Rust API 保持可用状态以备将来恢复
- 官方 relay 老客户端（HarmonyOS/Android、旧构建）打新 relay 得 404，属显式不支持
- 测试以协议层/集成测试为准；上线前按仓库惯例补一次真实双端远程控制手工验证（短信走真实签名模板或沙箱）
